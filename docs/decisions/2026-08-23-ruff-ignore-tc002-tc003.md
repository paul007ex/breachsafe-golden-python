# Ignore ruff TC002/TC003 in the golden Python scaffold; keep UP042, N818, PLR0913

- Date: 2026-08-23
- Status: Accepted
- Affects: `scaffold/template/pyproject.toml.jinja`, every repo rendered from it
- Related: issue #2, PR #1, `BreachSAFE/qureddy#427`

## Context

Pressure-testing the scaffold surfaced that the golden lint config is materially stricter
than `qureddy`'s, the most mature BQP repo. A repo rendered from this template and filled
with house-style BQP code fails `just lint` on its first run, which contradicts the
scaffold's own promise of a repo "consistent from the first commit."

Method: rendered a repo from `v1`, transplanted 1,636 lines of real production code
(`qureddy/src/qureddy/core`, 11 modules), ran the suite on Python 3.14.

`just lint` produced 18 errors on code that is green in qureddy CI today. The difference is
entirely configuration:

| | golden | qureddy |
|---|---|---|
| `target-version` | `py314` | `py313` |
| type-checking rules | `TC` | `TCH` (deprecated alias) |
| `ignore` | `E501` | `E501, PLR0913, PLR0917, UP042, N818, TC002, TC003, PTH113` |

Per-rule counts:

| Rule | Count | qureddy ignores | Decision |
|---|---:|:---:|---|
| `UP042` str+Enum, use StrEnum | 8 | yes | **keep enforcing** |
| `TC003` stdlib into type-checking block | 3 | yes | **ignore** |
| `TC002` third-party into type-checking block | 1 | yes | **ignore** |
| `I001` import sorting | 3 | no | keep enforcing |
| `N818` exception Error suffix | 1 | yes | **keep enforcing** |
| `PLR0913` too many arguments | 1 | yes | **keep enforcing** |
| `RUF100` unused noqa | 1 | no | keep enforcing |

## Options

**A. Golden stays strict. qureddy's 8 ignores are debt.** (score 6/10)
Defensible on the merits: `UP042` and `N818` are genuine modernisation, and `py314` is the
platform baseline, which is *why* `UP042` fires (`enum.StrEnum` exists). Cost: every new repo
starts red, and qureddy cannot adopt the reusable workflow without first clearing ~14 classes
of finding. Adoption stalls behind a cleanup project.

**B. Golden adopts qureddy's full ignore list.** (score 4/10)
Defensible: a standard should match what shipping BQP code actually passes, and qureddy is
the most mature repo. Cost: bakes today's debt into every future repo and silently drops real
modernisation rules. It also inherits `PTH113` and `PLR0917` with no stated reason.

**C. Scoped A: ignore only the rules with evidence of harm; enforce the rest.** (score 9/10) ← chosen
Ignore `TC002`/`TC003`, which demonstrably break the house style. Keep `UP042`, `N818`,
`PLR0913` as real, fixable signal. Record the delta so it is deliberate.

## Steelman

**Steelman of A:** `TC002`/`TC003` exist for a real reason. Runtime imports used only for
typing cost import time and can create cycles. A large codebase with a slow CLI start-up
feels that. Rejecting the rules outright gives up a genuine benefit, and the pydantic problem
has a documented workaround (`model_rebuild()`), so a disciplined team could keep the rules
and call `model_rebuild()` where needed.

**Why C still wins:** the workaround has to be applied correctly at every affected model, and
nothing detects a missed one until the model is first instantiated at runtime. The rule
cannot distinguish a pydantic field annotation from an inert one, so it issues advice that is
correct in general and wrong in this codebase's dominant pattern. A lint gate that can be
satisfied by introducing a latent runtime failure is worse than not running the rule. The
import-time saving is not measured anywhere and is not the constraint these CLIs face.

**Steelman of B:** consistency with the reference implementation has real value; a standard
nobody can pass is not a standard. **Why it loses:** `UP042` at 8 occurrences is exactly the
kind of drift the golden repo exists to stop, and `py313` vs `py314` means qureddy's config
was written for an older baseline rather than deliberately chosen against this one.

## Pressure-test evidence

The pydantic breakage is reproduced, not asserted. Following `TC003`'s advice:

```python
from __future__ import annotations
from typing import TYPE_CHECKING
from pydantic import BaseModel

if TYPE_CHECKING:                # exactly what TC003 instructs
    from datetime import datetime

class Evidence(BaseModel):
    seen_at: datetime

Evidence(seen_at="2026-08-23T00:00:00")
```

Result on pydantic 2.13 / CPython 3.14:

```
pydantic.errors.PydanticUserError: `Evidence` is not fully defined;
you should define `datetime`, then call `Evidence.model_rebuild()`.
```

Control, identical model with the import left at runtime:

```
model built OK: seen_at=datetime.datetime(2026, 8, 23, 0, 0)
```

Note the failure surfaces at **first instantiation**, not at import and not at lint. A repo
that follows the rule passes every gate and fails in production.

## Consequences

- Transplanted-code lint errors drop from 18 to 14. The remaining 14 are intentional: 8
  `UP042`, 3 `I001`, 1 `N818`, 1 `PLR0913`, 1 `RUF100`.
- The golden standard stays stricter than qureddy on 3 rules, now deliberately and on record.
- `qureddy#427` (collapsing its `INTERIM WIRING` gate onto the reusable workflow) still needs
  those 3 rule classes resolved on the qureddy side. Not addressed here by instruction.
- Not adopted from qureddy's list, for want of a stated reason: `PLR0917`, `PTH113`.
- Unrelated observation, not acted on: qureddy `select`s `TCH`, the deprecated alias for
  `TC`, while ignoring `TC002`/`TC003`. Worth confirming those ignores take effect there.
